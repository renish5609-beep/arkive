## Georeferencing policy

Arkive distinguishes exact, approximate, and unresolved historical locations.
Coordinates are only added when supported by address, archival map, parcel/GIS,
or other reviewable evidence. Approximate locations retain an uncertainty
radius and provenance record. Unresolved locations remain visible in the
research queue rather than being guessed.

Useful commands:

```bash
npm run validate:data
npm run georef:status
```

## Archival mentions

A mention is a raw occurrence of a name, place, or institution in a source
(`data/projects/quakertown/mentions.json`). A mention is not a person or place
record. It becomes part of a canonical record only when `linked_entity_id` is
set, which happens after the source supports the identity. Mentions that are
not linked remain visible on the source page and in the research queue.

To add a mention with validation:

```bash
npx tsx scripts/add-mention.ts --source source_004 --type person --raw-name "Alberta Woods"
```

## Entity resolution

Candidate identity matches are generated by deterministic rules in
`lib/entity-resolution.ts`. No language model is used. Each candidate lists the
reasons for and against the proposal. All new candidates are `pending`, and
generation never changes `linked_entity_id`.

Automated match scores are heuristics for prioritizing review. They are not
historical verification. A high score does not confirm that two mentions refer
to the same person or place.

## Research review workflow

1. Open a source and identify discrete mentions.
2. Add mentions first, leaving `linked_entity_id` empty when identity is unclear.
3. Run the candidate preview and review pending matches at `/review`.
4. Link a mention, or create a canonical record, only when a source supports it.
5. Add relationships only with direct evidence and a source.
6. Record open questions in the research queue rather than guessing.

## Dataset export

- `GET /api/export/quakertown?format=json` returns project metadata, people,
  places, relationships, sources, mentions, match candidates, and location
  evidence.
- `GET /api/export/quakertown?format=csv&entity=people` (also `places`,
  `relationships`, `mentions`, `sources`) returns a CSV with headers. Array
  fields are joined with semicolons.

Exports keep source IDs and verification metadata so that downstream users can
audit where each claim came from.

## Commands

```bash
npm run research:status
npm run matches:preview
npm run matches:write
npm run audit:provenance
npm run validate:data
```

`matches:preview` is a dry run. `matches:write` saves candidates and never
overwrites an accepted or rejected decision.
